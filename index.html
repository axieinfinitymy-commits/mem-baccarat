Game API Sandbox

Same platform shell, separate game engines and endpoints.

BACCARAT API
POST /api/v1/games/baccarat/launch
POST /api/v1/baccarat/tables/{tableId}/join
POST /api/v1/baccarat/rounds/{roundId}/bets
GET  /api/v1/baccarat/rounds/{roundId}
WS   /api/v1/live/baccarat/{tableId}
BLACKJACK API
POST /api/v1/games/blackjack/launch
POST /api/v1/blackjack/tables/{tableId}/join
POST /api/v1/blackjack/rounds/{roundId}/bets
POST /api/v1/blackjack/rounds/{roundId}/actions
WS   /api/v1/live/blackjack/{tableId}
NGAO API
POST /api/v1/games/ngau/launch
POST /api/v1/ngau/tables/{tableId}/join
POST /api/v1/ngau/rounds/{roundId}/bets
GET  /api/v1/ngau/rounds/{roundId}
WS   /api/v1/live/ngau/{tableId}
Production principle: browser UI is never authoritative for wallet balance, RNG, bet validity, game result, payout or settlement. Each game engine should run server-side with its own authoritative state.
